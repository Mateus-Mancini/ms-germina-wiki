# Data Model: folders-api

## Folder

Represents one Wiki folder and maps to the existing PostgreSQL `folders` table.

| Field | PostgreSQL column | Type / nullability | Mapping and behavior |
|---|---|---|---|
| `id` | `id` | UUID, primary key, required | Java `UUID`; generated by the application unless inspection confirms an existing database default to reuse. |
| `name` | `name` | VARCHAR(150), required | Java `String`; required, non-blank, maximum 150 characters. |
| `parentFolder` | `parent_folder_id` | UUID FK to `folders.id`, nullable | Optional self-reference; lazy owning-side JPA `ManyToOne`; no cascade or orphan removal. |
| `createdBy` | `created_by` | UUID FK to `users`, required | Java `UUID` from the authenticated principal. Keep as a scalar UUID; do not add or change a User entity/API. |
| `createdAt` | `created_at` | TIMESTAMPTZ, required | Java `Instant`; assigned when created, unless existing schema default is explicitly verified and reused. |
| `updatedAt` | `updated_at` | TIMESTAMPTZ, required | Java `Instant`; set on create and refreshed for each successful update. |

The exact schema, identifier defaults, timestamp defaults, FK names, and FK delete actions are not present in this repository. Verify them against PostgreSQL before finalizing JPA annotations. Keep Hibernate schema mode at `validate`; do not add migrations, DDL, indexes, or replacement tables in this feature.

## Relationships

- A folder has zero or one parent folder. A parent may have many child folders.
- The logical child list is exposed only through response DTOs. The initial JPA mapping need not maintain a bidirectional `children` collection.
- Every non-null `parent_folder_id` must reference an existing folder according to the existing FK.
- `created_by` references an existing user. The endpoint gets its UUID from the hosting authenticated principal.
- No name uniqueness or ownership restriction is assumed; neither is specified by the provided schema/requirements.

## Validation and invariants

- `name` is required, non-blank, and at most 150 characters. Apply Bean Validation at request boundaries; validate only supplied values in partial updates.
- A folder cannot be its own parent. A folder cannot be reparented beneath any of its descendants.
- Parent changes run in a transaction. Acquire the shared PostgreSQL transaction-scoped advisory lock before loading the ancestry and checking cycles; track visited IDs in the ancestry walk.
- A parent UUID that does not exist returns `404 Not Found`. Self-parenting or a cycle returns `409 Conflict`; rejected updates leave the previous relation unchanged.
- Delete does not cascade or reparent in application code. Honor the database FK action. A PostgreSQL FK violation is returned as `409 Conflict`; any DB-configured cascade/set-null action remains database-owned.

## State changes

- **Create**: application assigns UUID and timestamps, obtains creator UUID from the principal, stores optional parent, and returns the persisted representation.
- **Update**: omitted `name`/`parentFolderId` values remain unchanged. Explicit `parentFolderId: null` moves the folder to the root. Update `updated_at` only after a successful change.
- **Delete**: remove the requested row and let PostgreSQL apply its configured referential action or reject it. The feature adds no implicit child operation.

## API representations

- `FolderResponse`: `id`, `name`, `parentFolderId`, `createdBy`, `createdAt`, `updatedAt`.
- `FolderTreeNodeResponse`: the same folder fields plus `children`, an array of nested tree nodes. Roots have `parentFolderId: null`; leaves have `children: []`.
- List and tree queries use one flat projection and are assembled into DTOs. Entity graphs are never serialized directly.
